# 提供者持有的休眠数据

[English](provider-suspension.md)

## 适用范围

Blaze 可以在不保留活动数据面租约的情况下休眠由提供者支撑的沙箱。可选的
`DataPlaneSuspend` 扩展把守护进程持有的运行后端快照，与构建时提供者持有的
不可变数据面内容关联起来。恢复时必须准备新的独占租约，不得重新启用休眠时
已经释放的原租约。

只有构建时提供者明确提供休眠扩展时，Blaze 才会走这条路径。声明
`daemon_managed_storage` 的提供者（包括标准文件提供者）继续使用原有存储休眠流程，
不需要实现该扩展。持久化生命周期状态只保存可移植的提供者引用，不依赖某个扩展的
资源模型；这项资源归属记录不属于管理 HTTP 响应。

## 所有权模型

一份由提供者支撑的休眠映像有三个不同的责任主体：

| 责任主体 | 持久化责任 |
|---|---|
| Blaze | 沙箱生命周期、运行后端快照、制品散列值、操作阶段和公开休眠目录 |
| 提供者 | 不可变的根文件系统与客户机内存内容、内容清单及全部清理状态 |
| 共享合同 | 提供者实例、休眠、不透明引用和来源租约标识，逻辑容量与清单摘要 |

Blaze 在调用提供者之前分配休眠标识，使结果未知的捕获能够用同一标识重试。不透明
引用标识提供者返回的确切不可变对象。两者必须同时记录，因为请求可能已经产生副作用，
但调用方还没有收到准确引用。

引用不再分别记录各项资源的所有权。引用存在即表示同一个提供者持有一份内部一致的
完整映像，其中同时包含可写根文件系统视图和客户机内存视图。部分所有权不属于本合同，
因为 Blaze 尚未实现多个数据面所有者之间的原子捕获协调。

## 客户机恢复合同

由提供者支撑的休眠要求客户机通信通道和第一版协议。任何运行后端或提供者发生变更
之前，Blaze 先通过 `hello` 确认客户机具备以下操作：

- `prepare_hibernate`：确认客户机写入已经同步；
- `reseed_rng`：恢复后接收恰好 256 字节的新宿主机随机熵；
- `post_restore`：校正客户机实时时钟，并返回校正后的时间证据。

缺少任一操作时，休眠请求会在沙箱和提供者发生变更之前失败。产生副作用的客户机
操作如果响应失败或结果不明，不会被当作成功。随机状态重新播种和时钟校正都成功后，
Blaze 才能把恢复后的运行后端发布为运行中。

这些操作属于客户机行为，不属于数据面提供者能力。提供者不能替不兼容的客户机映像
声明或模拟这些能力。

## 休眠事务

成功流程依次为：

1. 校验活动的已最终确认租约、运行后端身份、恢复适配器和客户机操作；
2. 要求客户机同步写入；
3. 持久化休眠标识和 `Hibernating` 操作；
4. 暂停运行后端写入，并在暂停期间捕获完整运行后端快照；
5. 要求提供者在同一静止边界捕获不可变数据面内容；
6. 校验并持久化提供者引用和推进后的活动租约；
7. 计算守护进程制品的散列值，并同步制品与清单；
8. 终止运行后端，停止并释放活动提供者租约，持久化活动数据面已经不存在；
9. 原子发布休眠目录并转换为 `Hibernated`；
10. 只有替代映像已经持久化后，才回收旧休眠内容。

捕获返回 `OutcomeUnknown` 时，Blaze 不会直接重复捕获，而是检查活动租约，只接受调用前
的准确代次或增加一次后的准确代次，再按预先分配的休眠标识要求提供者回收可能产生的
内容。已知引用按完整的公开标识和提供者标识回收。运行后端终止之前，检查和清理均成功
后可以解除暂停并回到 `Running`；运行后端终止之后，或者无法证明检查或清理完成时，
Blaze 会保留预写所有权账本并进入 `RecoveryRequired`。

## 恢复事务

恢复首先校验公开清单、每个运行后端制品的散列值和提供者引用，然后依次执行：

1. 分配新的请求、操作和租约标识；
2. 要求提供者从不可变休眠内容准备一个新租约；
3. 校验路径型槽位，或者已经打开且类型明确的根盘与客户机内存附件，并记录替代租约；
4. 使用已校验的守护进程制品和提供者资源启动运行后端；
5. 校验运行后端身份、制品身份、存活状态和客户机协议；
6. 注入新随机熵，清零宿主机副本，并校正客户机时间；
7. 提交替代租约，并记录提供者提交边界；
8. 发布 `Running`，保留活动租约，并完成提供者所有权交接。

在 `Running` 发布之前失败时，只要能够证明清理完成，Blaze 会终止替代运行后端、
中止替代租约，并回到未改变的 `Hibernated` 映像。公开状态已经发布后的失败无法安全
回滚，因此进入 `RecoveryRequired`。

## 删除与回收

成功恢复后，休眠映像仍保持不可变和可达。只有下一次休眠替换该映像，或者删除沙箱时，
才会回收它。Blaze 先持久化待回收记录，再删除公开所有者，最后请求提供者回收内容。
已知引用和结果未知的捕获使用不同请求形状，因此管理器不需要自行构造不透明的提供者标识。

删除还必须在提交终态 `Destroyed` 前释放活动租约和替代租约。只要终态记录仍包含活动
租约、替代租约、休眠引用或待回收的休眠数据，该终态记录就不合法。

## 提供者要求

实现 `DataPlaneSuspend` 的提供者必须：

- 按预先分配的休眠标识保证 `suspend` 幂等；
- 从静止的来源租约捕获一致的根文件系统和内存视图，并把已最终确认租约准确推进一代；
- 在来源租约释放后继续保证休眠内容不可变；
- 按新的 `RequestContext` 保证 `resume` 幂等，返回容量准确且与来源不同的新准备态租约；
- 返回一个有效的路径型槽位，或者一组完整且类型明确的已打开附件；
- 以提供者实例、公开休眠和可选引用组成的完整身份作为幂等回收键，并在守护进程
  重启后接受同一个确定性派生的操作标识；
- 保存足够的持久状态，以便守护进程中断后完成清单核对和人工恢复。

休眠扩展与检查点扩展彼此独立。提供者可以只实现其中任意一项，不要求同时实现另一项。

## 验证边界

公开测试已经覆盖合同校验、客户机能力协商、随机熵与时钟响应校验、活动租约释放、
新租约恢复、在完整休眠状态重启守护进程、启动时重试旧休眠内容回收、不兼容客户机的
变更前拒绝、运行后端启动失败后的重试，以及删除时回收休眠内容。

当前管理器对未完成的休眠或恢复事务采用保守策略：启动时先根据预写账本检查并收敛
提供者结果，再按已知事务完成幂等清理，不猜测副作用是否发生。生产提供者仍需在 Linux 环境中验证真实运行
后端和客户机行为、多轮休眠与恢复、每个已持久化阶段的进程终止、提供者和客户机结果
不明、并发操作、内容完整性，以及删除后无资源残留。
