# 提供者持有的检查点

[English](provider-checkpoints.md)

## 范围

Blaze 可以把守护进程持有的后端快照制品，与构建时数据面提供者持有的不可变内容组成
一个检查点。这是 `DataPlaneProvider` 的可选扩展：只有编译进最终二进制的提供者公开
`DataPlaneCheckpoint` 时，提供者沙箱才走该路径。声明 `daemon_managed_storage` 的
提供者（包括标准文件提供者）继续使用原有存储检查点流程，不需要实现该扩展。

合同通过有界的不透明标识和完整性摘要表示扩展持有的内容。每个提供者负责物化和校验
这些标识指向的内容，使文件、设备或服务支撑的实现能够共用同一套 Blaze 检查点目录。

资源归属引用属于恢复过程使用的持久化检查点清单，不属于管理 HTTP 响应。接口调用方
仍只会收到公开检查点标识、谱系、运行后端、快照类型和制品元数据，不会得到提供者租约
或内容标识。

## 所有权划分

一个公开检查点只有在边界两侧同时成立时才完整：

| 所有者 | 持久内容 |
|---|---|
| Blaze | 公开检查点 UUID、沙箱及运行时身份、父节点、后端载荷和哈希 |
| 提供者 | 可写根盘和客户机内存内容、提供者管理的谱系及内容元数据 |
| 共同合同 | 提供者实例 UUID、公开检查点 UUID、不透明引用 UUID、父引用、来源租约代次及提供者清单摘要 |

公开检查点 UUID 与不透明引用 UUID 有意分离：前者把载荷绑定到公开目录项，提供者按照
自己的标识规则解析后者。任一标识为空、公开标识与目录位置不一致，或者摘要不是规范
SHA-256 时，Blaze 都会拒绝该记录。

引用不再分别记录各项资源的所有权。引用存在即表示提供者持有一份内部一致的完整映像，
其中同时包含可写根文件系统和客户机内存。Blaze 不支持、也不表达部分所有权，因为这需要
另一个原子协调器来协调独立提交的多份载荷。

## 捕获事务

Blaze 在任何提供者副作用前分配公开检查点标识，并用它作为捕获幂等标识。顺序如下：

1. 校验当前父检查点，并分配尚未发布的目录暂存区；
2. 停止后端写入，持久化暂停操作边界；
3. 在写入仍停止时捕获后端状态；
4. 要求提供者在同一个停写边界冻结数据面内容；
5. 持久化已增长代次的活动租约，并把提供者引用记录为待回收；
6. 原子发布公开清单并更新生命周期日志；
7. 只有公开发布持久化后才移除待回收标记；
8. 恢复后端并结束公开操作。

捕获返回 `OutcomeUnknown` 时，Blaze 不会直接重复捕获，而是检查活动租约，只接受调用前
的准确代次或增加一次后的准确代次。随后按预先分配的公开检查点标识要求提供者回收可能
产生的内容，不自行构造提供者对象标识。对于已知但尚未发布的引用，会按完整的公开标识
和提供者标识完成回收后再恢复后端；若无法证明检查或回收完成，沙箱进入
`RecoveryRequired`，持久的预写标识继续留给启动恢复。

## 恢复事务

回退不会复用活动租约或其设备。当前后端仍在运行时，Blaze 先要求提供者从不可变引用
准备一个独立的替换租约，并在停止旧后端前将其持久化。

旧后端和旧租约停止后，Blaze 使用守护进程持有的后端载荷，以及提供者返回的路径型槽位
或带类型的已打开附件启动替换实例。验证后端身份和就绪状态后，才提交替换租约；随后
依次更新检查点 `HEAD`、释放前任租约、把替换租约原子提升为公开沙箱的活动租约、发布
`Running`，最后完成提供者所有权交接。

旧后端停止前的失败会中止替换租约，原运行沙箱保持不变。越过停止边界后，旧活动实例
已无法安全重建；Blaze 会尽可能终止不可信替换后端，保留清理所需的两份持久所有权记录，
并把沙箱标为 `RecoveryRequired`，不会把半就绪替换实例发布为运行中。

`RestoreCheckpointRequest` 接收新选择的 `RequestContext`，因此提供者合同可以为原地
回退或未来的克隆操作准备独立租约。公开 HTTP API 只实现原地回退；目前没有从检查点
创建新沙箱的端点和策略合同，不得宣称已支持克隆。

## 回收与删除

公开可达性是权威依据。裁剪先计算并持久化所有可能需要回收的提供者引用，再删除不可达
的公开目录项；只有已证明公开目录项删除的内容才会交给提供者回收。每次成功回收都会
单独清除持久待处理标记，因此崩溃后的重试仍然幂等。

删除沙箱采用相同顺序：盘点提供者引用、持久化待处理列表、删除公开检查点命名空间，
再回收提供者内容。仍有公开目录项持有引用时绝不删除对应内容。提供者还必须自行保护
被提供者谱系中的后代或已独立准备租约引用的内容。

## 提供者要求

`DataPlaneCheckpoint` 实现必须：

- 以预选公开检查点 UUID 实现幂等捕获；
- 返回活动已完成租约严格增长一个代次后的状态；
- 冻结内部一致且不可变的根盘和内存视图；
- 恢复时验证引用谱系和规范清单摘要；
- 返回新的独占准备租约，而不是来源活动租约；
- 以提供者实例、公开检查点和可选引用组成的完整身份作为幂等回收键，并在守护进程
  重启后接受同一个确定性派生的操作标识；
- 在 Blaze 删除相应公开所有者前保留内容。

一致性软件包会校验实现无关的标识、状态转换、谱系、附件形状和回收结果；它不能证明
提供者内容清单的正确性，也不能证明真实后端观察到同一个准确停写点。

## 验证边界

单元测试覆盖提供者捕获、以独立租约回退、目录删除后的裁剪、只有后端载荷的公开
检查点、身份校验，以及公开发布失败时的补偿。生产提供者仍需提供 Linux 集成和故障
注入证据，覆盖并发捕获、多级谱系、每个持久边界上的守护进程重启、同一引用多次恢复，
以及后代仍可达时删除来源对象。
