# 构建时数据面提供者

[English](build-time-data-plane-providers.md)

## 目的

Blaze 提供源码级数据面合同，使下游开发者可以在不修改 Blaze 源码树的情况下，把自定义
资源实现与守护进程组合成一个二进制文件。最终实现由构建过程确定，不从插件目录发现，
不由租户请求选择，也不能通过标准守护进程配置切换。

标准 `blazed` 二进制始终使用现有文件实现。下游开发者可以在扩展软件包中实现
`DataPlaneProvider`，把 `blazed` 作为库依赖，再将实现交给
`BlazeDaemonBuilder`。

## 兼容边界

该合同是 Rust 源码接口，不是稳定的动态库二进制接口。提供者二进制必须固定彼此兼容
的以下内容：

- `blaze-provider-api`；
- `blaze-provider-conformance`；
- `blazed` 与 `blaze-core`；
- Rust 工具链；
- 最终构建使用的依赖锁文件。

`ProviderDescriptor.contract_version` 可以在运行时拒绝明显不匹配的合同版本，但不能
替代源码版本和依赖版本固定。

## 生命周期状态命名空间

配置项 `daemon.state_dir` 仍是进程协调根目录。标准 `blazed` 二进制继续把生命周期
记录直接保存在该目录下，原有布局保持不变。通过 `BlazeDaemonBuilder` 组合的守护进程
默认改用以下稳定规则派生实际状态根：

```text
<daemon.state_dir>/.provider-state-v<contract_version>-<provider_instance_id>
```

提供者标识采用规范的小写带连字符 UUID。派生目录是协调根的直接子目录，完整目录名
本身不可能是 UUID。因此，只扫描 `daemon.state_dir` 下一层 UUID 子目录的标准守护
进程，包括旧版本，都不会载入、改写或清理提供者扩展的生命周期记录。降级安全依赖
这一目录边界，而不依赖旧版序列化程序如何处理无法识别的字段。

Blaze 会先校验配置中的外层根目录，再在创建自身持有的目录前校验派生后的实际根目录。
启动后会持续持有外层根目录和所选命名空间的排他锁。命名空间通过已打开的外层目录
描述符创建和打开，并且不会跟随命名空间位置的符号链接。只要配置根目录的目录项仍然
指向已经打开的对象，外层锁就能阻止两个遵守该协议的守护进程同时持有该对象。

因此，配置的状态根目录及其父目录属于守护进程信任的宿主机配置：守护进程运行期间
不得重命名或替换完整状态根，也不能允许不可信用户修改其父目录。目录锁绑定已经打开
的文件系统对象，而不是路径字符串；替换完整根目录会产生带有另一把锁的新对象。已经
保留的目录描述符仍能阻止现有状态读写被重定向，但不能把一条可替换路径变成宿主机
范围内的唯一实例锁。服务管理和目录权限必须落实这一既有部署要求。

接受自定义提供者前，启动流程会以只读方式检查标准根目录以及其他提供者命名空间，
不会代替原提供者清理这些记录。只要发现非终态记录、未完成的状态发布、损坏的所有权
记录或并发变化，启动就会停止。只有其他身份的全部遗留记录都能证明为不再持有任何
资源的合法 `Destroyed` 记录时，才允许使用新身份。这样，修改
`provider_instance_id` 不能静默接管或绕过仍然存活的状态。

组合程序必须在提供者所有权域的整个生命周期内保持 `provider_instance_id` 稳定。
修改提供者标识或合同版本会选择另一个命名空间；Blaze 不会在命名空间之间自动迁移或
复制记录。有意更换身份前，必须先使用原提供者完成清理。同样，降级后运行标准二进制
不会清理只记录在扩展命名空间中的资源；应先使用兼容的扩展二进制结束这些生命周期。

该命名空间保存 Blaze 的生命周期记录，并不替代提供者自身的持久资源账本。后者的
位置和恢复规则仍由扩展自己的配置与文档定义。

标准文件提供者把所有权账本放在实例根目录下受保护的同级目录中，而不是放进任何会被
递归删除的沙箱目录。它在创建槽位前写入完整的准备请求身份，只在制品持久化后把记录
标为就绪，并在递归删除前把记录标为删除中。只有空槽位及其父目录已经同步后，才删除
账本记录。因此，启动恢复可以继续每个中断的分配或删除操作，同时不会把没有记录的
同名目录误判为自身资源。启动时只会清理命名格式严格匹配、由原子账本更新遗留的未
发布临时记录，不会把账本中的其他条目当作可丢弃内容。

文件提供者会根据实例根目录的规范路径对象、文件系统设备号和索引节点号确定性地派生
`provider_instance_id`。使用同一个根目录重建提供者时，身份保持不变；改用另一个根
目录或替换原根目录对象时，身份随之改变。因此，旧绑定会在查询或删除前返回冲突，
不会因为新配置的根目录为空就被误报为已经释放。这个根据根目录派生的描述信息遵循构建
时生命周期状态命名空间对组合提供者身份稳定性的同一项要求。

每条就绪账本记录都会保存从已经打开的槽位目录读取的设备号和索引节点号。分配流程
不会把随机标记或槽位路径名当作所有权证据。如果无关目录在创建槽位前抢占了同名位置，
准备中记录仍然没有目录身份，清理操作会拒绝触碰该目录。如果进程恰好在创建目录后、
发布目录身份前退出，同样会保留这个身份不明的目录，等待运维人员核查。查询和清理都
会先比较当前链接的目录与账本记录的具体对象，再读取或删除内容。

重启后的查询会扫描全部规范命名的所有权清单。因此，只要实例标识或租约标识在不同的
完整上下文中被重复使用，提供者就会返回类型明确的冲突。完全相同的重复准备请求还会
比较来源指纹、根文件系统和内存的逻辑长度，以及模板虚拟机状态文件的长度。接受就绪
记录前，提供者会核对根文件系统与内存文件的逻辑长度；模板记录还必须包含普通的
`backend` 目录，以及长度符合记录的 `vmstate.snap` 和 `memory.snap` 文件。普通基础
镜像的原始长度也必须与请求合同一致，才允许复制。

初始代次必须为从创建到释放的完整流程预留足够空间。后续状态转换会在开始任何清理前
先计算下一代次；如果发生溢出，操作会返回冲突并保留资源，不会形成无法重试的删除结果。

文件提供者会持续持有已经打开的实例根目录的非阻塞排他锁。这是合作进程之间的单写者
约定，不能防御具有宿主机高权限的管理员。所有写入该根目录的程序都必须使用同一把锁，
部署权限也必须阻止无关进程在 Blaze 运行期间修改根目录、账本或槽位目录树。
如果实例根目录允许组用户或其他用户写入，文件提供者会拒绝使用；所有权账本目录只允许
目录所有者访问。

## 可复现且保护隐私的构建

Rust 工具链可能在诊断信息和元数据中保留绝对源码路径。为了得到可复现的分发制品，
应使用稳定的源码根目录，或通过 `rustc` 的 `--remap-path-prefix` 重映射构建路径；
Cargo 依赖路径也应采用同一规则。分发包只包含 Git 跟踪的源码和明确声明的发布制品，
不得复制 `.git`、`target`、本地配置或测试生成文件。

这些检查用于保证可复现性、开发者隐私和部署凭据安全，不能代替对已交付行为的说明。
发布前，应把归档文件清单与声明的发布输入逐项比较，并检查二进制中的可打印字符串，
确认没有意外包含本机路径、主机标识、凭据或未声明的配置。扩展有意发布的产品标识和
设置应在该扩展的发布说明中明确记录。

## 生命周期合同

基础合同只覆盖沙箱创建和删除。每次修改都绑定预先选定的沙箱标识、请求标识、操作
标识、租约标识和代次。成功流程如下：

| 操作 | 必须满足的语义 |
|---|---|
| `probe` | 在不分配沙箱资源的前提下检查依赖和权限。 |
| `prepare` | 创建一个由提供者持有的租约，并返回路径资源或已打开恢复资源。 |
| `inspect` | 在不修改资源的前提下观察已知租约的准确状态。 |
| `commit` | 在发布公开状态前，确认后端已经就绪。 |
| `finalize` | 在匹配的公开状态持久化后完成所有权交接。 |
| `stop` | 记录后端已经停止使用资源，同时保留清理所有权。 |
| `release` | 证明已停止租约持有的全部资源都已删除。 |
| `abort` | 撤销尚无持久公开所有者的准备中或已提交租约。 |

每次成功转换必须保留相同的提供者、请求、操作和租约标识，并且只把代次增加一次。如果
调用可能已经产生副作用却无法确认结果，提供者返回 `OutcomeUnknown`；Blaze 会先调用
`inspect`，再判断能否安全补偿。

`prepare` 可以返回两类资源：

- `PreparedResources::PathBacked`：保留现有文件存储布局；
- `PreparedResources::OpenedRestore`：为经过校验的模板恢复转交带类型的根盘和客户机
  内存描述符。

只有提供者声明对应能力时，Blaze 才接受已打开资源。Blaze 会在启动后端前核验租约和
资源形状。如果资源形状无效，但返回的租约绑定仍能安全识别，Blaze 会调用 `abort`；
Blaze 不会使用不可信绑定执行补偿。

## 组合方式

扩展软件包实现 `DataPlaneProvider`，定义所需的资源配置和持久状态，并把实现错误映射为
与提供者无关的 `ProviderError` 类别。面向具体用途的命令程序作为组合入口。仓库内提供
两个可以执行的示例：

- [`minimal_provider.rs`](../../crates/blaze-provider-conformance/examples/minimal_provider.rs)
  使用完整的基础接口实现运行可复用的创建和删除检查；
- [`custom_provider_daemon.rs`](../../crates/blazed/examples/custom_provider_daemon.rs)
  将同一个提供者交给 `BlazeDaemonBuilder` 并启动守护进程。

在 `src/blaze` 目录中构建并检查这两个入口：

```bash
cargo run -p blaze-provider-conformance --example minimal_provider --locked
cargo run -p blazed --example custom_provider_daemon --locked -- --help
```

守护进程示例直接接收 `--daemon-config <路径>` 和
`--resource-root <绝对目录>`，不使用标准二进制的 `daemon start` 子命令。共享的
`ExampleFileProvider` 会创建真实稀疏文件，但有意不实现持久化和任何可选扩展。生产
提供者还必须验证真实后端、失败补偿、并发和故障恢复。

构建器会在 Blaze 创建守护进程目录前核验提供者描述并执行 `probe`。探测失败会直接
终止启动，不会构造标准文件提供者来替换失败的构建时提供者。

## 扩展配置

`DaemonConfig` 与具体提供者无关，也不能在运行时选择构建时扩展。每个扩展在自己的
软件包和组合二进制中定义所需配置和资源映射。扩展返回 Blaze 的值仅限公开、与具体
实现无关的类型和稳定的 `ProviderError` 类别；Blaze 不接收提供者生成的任意错误文本。
扩展代码如需输出额外诊断，应由开发者按照部署环境的日志策略自行实现。

通过管理接口返回的名称属于扩展的版本化产品合同，应由扩展维护者明确说明。传输端点、
资源映射和提供者专用设置留在提供者软件包及其运维文档中，使 Blaze 配置可以被彼此
独立的实现复用。

Blaze 为沙箱和检查点清单使用明确的管理响应结构。这些结构包含已经说明的生命周期、
策略、运行后端和制品字段，但不包含数据面租约、恢复记录或提供者检查点引用。因此，
在构建时选择提供者不会暗中扩展 HTTP 响应结构。

Blaze 自身的贡献也遵循可复用合同原则。公开类型、注释、示例、测试材料和诊断信息只
描述可观察的资源角色、能力、生命周期结果和稳定错误类别。示例必须仅依靠 Blaze
仓库跟踪的源码即可理解和运行。提供者专用资源拓扑和配置由相应提供者自行定义和说明。

文件沙箱和守护进程持有的目录仍要求配置现有 `[storage]` 文件目录。主要数据面提供者
通过基础合同改变创建和删除。它可以声明 `daemon_managed_storage`，让检查点、休眠和
恢复使用配置的存储提供程序；也可以单独选择由提供者持有内容的生命周期扩展。仅仅存在
提供者租约并不要求实现这些扩展，也不会静默获得任何可选行为。

## 已支持和暂缓的行为

| 场景 | 当前状态和前置条件 |
|---|---|
| 使用路径资源从普通镜像创建 | 支持 |
| 使用路径资源从模板创建 | 支持 |
| 使用已打开根盘和客户机内存资源从模板创建 | 要求提供者声明能力，并使用目前唯一能够消费此类资源的 Firecracker 恢复适配器 |
| 使用已打开恢复资源从普通镜像创建 | 在启动后端前拒绝 |
| 构建时提供者探测失败 | 启动失败，不回退文件实现 |
| 守护进程重启后接管提供者租约 | 要求实现可选资源清单合同，且后端支持按身份接管 |
| 提供者持有的检查点和回退 | 要求实现可选检查点合同，且后端完整支持快照与恢复 |
| 从提供者检查点创建新沙箱 | 暂缓；尚无公开端点和策略合同 |
| 提供者持有的休眠和恢复 | 要求实现可选休眠合同、后端完整支持快照与恢复，并具备文档规定的客户机协议操作 |
| 提供者持有的可复用数据面容量和排空 | 通过可选容量合同支持 |
| 可复用运行后端、网络和完整沙箱资源池 | 不支持 |
| 运行时发现动态库或进程插件 | 不支持 |

不支持重启接管的提供者不能被描述为适合持久工作负载的生产实现。资源清单合同及其
故障关闭规则见[提供者重启核对](provider-reconciliation_zh.md)。检查点所有权和补偿规则
见[提供者持有的检查点](provider-checkpoints_zh.md)。休眠所有权、客户机恢复操作和失败
处理见[提供者持有的休眠数据](provider-suspension_zh.md)。可复用数据面容量的查询和排空
规则见[提供者数据面容量](provider-capacity_zh.md)；该能力不提供完整的可复用沙箱资源池。

## 验证要求

扩展实现至少应完成：

1. 使用隔离资源运行 `blaze-provider-conformance::exercise_create_delete`；
2. 覆盖全部结果不明和失败补偿分支；
3. 证明不支持的来源会在产生副作用前失败，并且不会选择另一个提供者；
4. 证明真实后端使用的正是租约返回的资源；
5. 删除后确认不存在活动后端、附件、提供者资源或仍可领取的租约；只有不再持有资源的
   幂等记录或清理标记可以保留；
6. 确认面向 Blaze 的接口、日志、指标和一致性证据遵守公开合同，并在扩展自身的开发者
   文档和运维文档中完整说明其资源模型。

一致性软件包只核验与提供者无关的状态和资源形状；具体扩展仍需自行证明正确性和生产
就绪程度。
