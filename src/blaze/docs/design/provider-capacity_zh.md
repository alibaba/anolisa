# 提供者数据面容量

[English](provider-capacity.md)

## 适用范围

可选的 `DataPlaneCapacity` 扩展用于查询和排空构建时提供者持有的可复用数据面资源。
它不创建或管理可复用沙箱实例、运行后端进程、网络命名空间、处理器配额或客户机状态。
每个扩展把自己的资源映射成 Blaze 接口公开的提供者无关容量类别。

容量按照 `CapacityScope` 分区。一个分区由使用资源的运行后端和提供者无关的资源类别
准确确定。`CapacityClass` 声明该类别中每项资源都能支持的最大根文件系统和客户机内存
逻辑范围。这两项可移植要求可以在不同提供者实现之间唯一确定同一个类别。

容量为零表示该类别的复用资源没有预先分配对应附件角色；两个容量不能同时为零。后续
`prepare` 仍可在同一租约事务中冷创建缺少的角色，但不能把该冷创建资源计入复用容量。

类别标识是以下内容的 SHA-256：域字符串 `blaze.data-plane-capacity.v1\0`，随后是两个
采用网络字节序的 64 位无符号容量。任一要求改变都会产生新标识，不同实现提供相同要求
时则产生相同标识。提供者不持有请求分区时必须拒绝，不能返回另一个分区，也不能悄悄
改用文件资源。即使一项物理资源也能满足更小类别，也只能计入一个类别。

## 完整状态划分

一份容量快照中的每项资源必须且只能属于以下一种公开状态：

| 状态 | 含义 |
|---|---|
| `ready` | 空闲、已经完整核验，可以由一个新租约安全领取 |
| `building` | 仍在创建、清理或核验，不能领取 |
| `in_use` | 由一个活动租约独占，且没有被选中排空 |
| `draining` | 不再复用，并将在当前工作允许后立即删除 |
| `quarantined` | 因所有权或清理结果未解决而隔离，不能分配 |

五种状态互斥。活动资源被选中排空后，从 `in_use` 转为 `draining`；即使它仍在为原租约
服务，也不能在两个计数中重复出现。隔离资源也不同时计入排空状态，必须由运维人员明确
处理后才能转换为后续状态。

`CapacitySnapshot::checked_total` 对五个计数做带溢出检查的求和。提供者身份或分区不符、
两个资源容量都不存在、类别摘要与公开要求不符、版本为零或计数求和溢出的快照都会被
Blaze 拒绝。版本由提供者单调分配，公开合同不会用墙上时钟推测版本。

`accepting_allocations` 表示 `prepare` 是否可以从该分区领取资源。它与瞬时 ready 数量
相互独立：健康但暂时为空的类别仍可允许冷创建；排空一经接受，返回前必须将其设为
`false`。

## 领取与回收边界

容量扩展不提供公开的领取或回收方法。这两个动作继续属于基础提供者生命周期：

- `prepare` 可以原子领取一个 `ready` 资源，并把它绑定到新租约；
- `release` 可以把已经彻底清理的资源放回 `ready`、直接删除，或者转入 `quarantined`；
- 容量不足时返回明确的提供者错误，不得选择另一个数据面。

把领取操作留在 `prepare` 内，可以维持单一租约事务，避免调用方先领取资源、随后却无法
完成绑定。

## 排空语义

`drain` 只作用于一个准确分区，并携带稳定的 `operation_id`。使用同一标识重复请求时，
提供者必须返回同一次已接受操作的结果。接受排空后：

- 空闲的 `ready` 资源立即删除，并计入 `removed_ready`；
- 尚未完成的 `building` 资源取消创建或转入 `draining`；
- 活动的 `in_use` 资源转入 `draining`，继续服务原租约，释放后再删除；
- `quarantined` 资源继续隔离，等待运维人员明确处理。

返回的快照表示提供者接受排空后的状态。`deferred_in_use` 表示必须等待活动租约释放的
资源数量，不能大于返回快照中的 `draining`。排空不会终止沙箱、撤销租约，也不承诺所有
延迟删除的资源已经消失。接受排空后的快照中 `ready`、`building` 和 `in_use` 必须均为
零，且 `accepting_allocations = false`；仍在服务原租约的资源只能计入 `draining`。

返回 `OutcomeUnknown` 时，Blaze 使用同一个操作标识重试。提供者必须持久保存足够的
操作状态，使自身重启后仍能回答该重试。第二次仍然结果不明时，Blaze 会把错误返回给
调用方，不会把它当作成功。

## 网络接口

守护进程把可选扩展映射为两个带分区的接口：

- `GET /v1/pools/{backend}/{class}` 返回公开类别要求、五个计数、带溢出检查的总数、
  分配状态和提供者版本；
- `POST /v1/pools/{backend}/{class}/drain` 排空该分区。请求体可以为空，也可以包含
  `{"operation_id":"<uuid>"}`。调用方需要关联重试时，应显式提供该标识。

`{class}` 是上述 64 字符小写摘要。接口只能访问守护进程当前启用的运行后端。格式错误
的后端或类别摘要返回 `400`，合法但未启用的后端或提供者不持有的类别返回 `404`；构建
时提供者没有实现 `DataPlaneCapacity` 时返回 `501`，并且不产生副作用。响应使用上述
与提供者无关的类别标识和资源汇总状态。

`GET /v1/pools` 和 `PUT /v1/pools/{backend}/{class}/sizing` 仍为保留接口并返回 `501`。
因此当前接口既不会虚构跨分区清单，也不会公开容量调整策略。

## 提供者要求

实现 `DataPlaneCapacity` 的提供者必须：

- 为每个分区维护持久且互斥的资源状态，并禁止把同一物理资源重复计入不同类别；
- 返回准确的分区和提供者身份，以及单调且非零的版本；
- 返回与类别摘要匹配的规范公开要求；
- 在 `prepare` 内保证领取操作的独占性；
- 旧绑定和可写数据全部清除后，才能把释放的资源重新标记为 `ready`；
- 禁止分配 `building`、`draining` 和 `quarantined` 资源；
- 按操作标识保证排空幂等，在确认前停止新分配，并保留活动租约；
- 在后续释放或恢复流程中完成延迟删除；
- 明确报告容量耗尽，不创建账本外资源，也不更换提供者。

## 验证边界

公开测试覆盖规范类别标识、快照计数、准确的分区和提供者身份、溢出拒绝、标准提供者
不支持时的行为、与提供者无关的网络响应结构、未启用、未知或格式错误的分区拒绝，以及
排空响应幂等。

公开测试不能证明具体提供者的资源清理、模板无关性、并发领取独占性、重启恢复，或者旧
租约数据确已清除。这些性质必须由提供者在目标操作系统上完成集成测试，并在创建、领取、
绑定、回收、排空和隔离转换处注入失败。
